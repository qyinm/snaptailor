Gandalf supports three agents today: Codex, Claude Code, and Cursor. Each agent exposes a different set of directories, files, and marketplace integrations, so not every operation behaves the same across all three. This page maps what Gandalf can discover, check, apply, browse, modify, and restore for each agent, and where the boundaries are.

## Discovery and inventory

Gandalf inspects user-global directories and agent-native project files for each supported agent. For Codex, it reads:

- `~/.codex/config.toml` for agent-level settings
- User hooks and skills
- Managed plugin skill inventory
- Project `.codex/config.toml` and `AGENTS.md` when present

For Claude Code, it reads:

- `~/.claude/settings.json`
- Skills and hooks
- Marketplace source metadata
- Project `.mcp.json`, `.claude/settings.json`, and `CLAUDE.md` when present

For Cursor, it reads:

- User `~/.cursor/mcp.json`, `~/.cursor/hooks.json`, and `~/.cursor/skills/`
- Project `.cursor/mcp.json`, `.cursor/hooks.json`, and `.cursor/skills/`
- Cursor Agent CLI config: user `~/.cursor/cli-config.json` and project `.cursor/cli.json` (scan/snapshot on the same `cursor` agent; not a separate import schema)
- Compatibility skill roots such as `.agents/skills/` where Cursor would load them

<Note>
  The Setup Console inventory shows user-global and managed rows. Project-local evidence is still discovered by `gandalf scan` and used by `gandalf check` / `gandalf apply`. Gandalf does not offer provider-backed TUI mutations for project-local rows, OpenCode, or Pi Agent.
</Note>

## Project-only check and apply

`gandalf check --project-only` (and the packaged GitHub Action) compare `gandalf.toml` with committed repository agent files, not user-home configs:

- Claude Code: `.mcp.json`
- Cursor: `.cursor/mcp.json`
- Codex: `.codex/config.toml`
- Declared skill sources and `[env_template]` keys referenced by MCP servers

`gandalf apply --project-only` writes those same MCP files. It reconciles undeclared project servers so the CI check can pass, re-reads disk at apply time after Review Changes, and leaves `${ENV}` templates uninterpolated. Default `gandalf apply` remains user-home Smart Merge and still preserves personal servers.

## Marketplace browsing

Codex and Claude Code can browse and inspect source-backed marketplace entries that Gandalf discovers in the agent directories. Gandalf presents these entries as they are defined by the source, so you can view descriptions, versions, and configuration details before deciding whether to apply any changes.

Gandalf does not own or certify the catalogs it browses. It surfaces what it finds in the agent directories, and any action that changes your setup is gated by Review Changes.

## Provider-backed actions

A Provider-backed action is only available when Gandalf has a concrete provider that can preview what will change and execute it safely. If an action does not have a provider, Gandalf shows the reason it is unavailable rather than silently skipping it. This applies to Codex, Claude Code, and Cursor.

## Marketplace-originated Review Action

Codex and Claude Code handle marketplace actions differently today:

- **Codex:** Gandalf offers non-mutating setup guidance for marketplace plugins when the source metadata is sufficient to render a preview. This lets you see what a plugin would configure without applying changes.
- **Claude Code:** For eligible user-scope marketplace plugins, Gandalf offers reviewed install with verified rollback. Review Changes runs before the install proceeds, so you can inspect the impact.
- **Cursor:** There is no Cursor marketplace install provider.

For all agents, marketplace updates, uninstalls, and add/remove-source operations remain unavailable when a mutation provider does not exist.

## Review Changes and restore safety

Supported agents share the same safety model around restore:

- **Content-backed snapshot:** Requires `--agent <codex|claude-code|cursor> --scope user`. Otherwise, create a metadata-only snapshot. `--project-only` apply also captures the project MCP files it writes.
- **Dry-run restore:** The default restore mode previews changes without writing them.
- **Apply restore:** Requires `--apply`, plus `--experimental` or `GANDALF_EXPERIMENTAL=1`.
- **Rollback:** Supported where the provider offers verified rollback.

Before any mutating restore, Gandalf creates a snapshot so you can undo if needed.

## Out of scope

The following areas are not covered by Gandalf today:

- OpenCode and Pi Agent (legacy scanners are not on the default product path)
- Cursor team/cloud-distributed hooks (reported as a local blind spot)
- Provider-backed TUI mutations of project-local rows
- Managing project `.env` files as a secret store
- Cursor marketplace install, update, or uninstall
- Default `gandalf apply` writing repository files (use `--project-only`)

## Future direction

Planned expansion for Gandalf includes:

- Broader team sync workflows across multiple workstations
- Cloud-managed setup and remote configuration workflows
- Additional agent providers and mutation providers
- A background setup-change daemon for continuous drift detection
